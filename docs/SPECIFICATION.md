# 実装仕様 — v0.1.0

更新日: 2026-09-10。現行コードを基準とする仕様です。

## 対象と構成

個人利用のローカル3Dモデリングアプリ。日本語の3パネルGUI（指示、プレビュー、API設定）をブラウザで表示し、Node.jsが設定した推論先へ中継します。モデル本体とBlenderは同梱しません。

| 項目               | 実装                                                   |
| ------------------ | ------------------------------------------------------ |
| UI                 | React 19.1.1 / TypeScript / CSS                        |
| 3D                 | three.js 0.180.0、WebGL2、OffscreenCanvas              |
| ローカルAPI        | Node.js標準HTTPサーバー、127.0.0.1限定、既定4173番     |
| 推論API            | OpenAI互換Chat Completions。画面の生成はストリーミング |
| ビルド / 圧縮      | Vite、esbuild / fflate、ZIP                            |
| システムプロンプト | v2を採用。v3は実験記録のみ                             |

## 操作

- 自然文で新規生成、現在版のソースを行番号付きで渡す追加修正。追加修正はソース全文の再生成を基本とし、少数の行に収まる局所的な変更には指定行の部分編集も使える。
- PNG / JPEG / WebP参照画像1枚。最大1,024pxに縮小。
- 現在版の正面・側面・斜めの3画像を修正時に添付。各640px、グリッドを除いて撮影。参照画像との合計は最大4枚。
- 経過時間・処理状態・停止。生成中の出力は「生成の詳細」にストリーミング表示する。コードを実行するのは正常終了後だけ。
- 左ドラッグで回転、右またはShift+ドラッグで移動、ホイールでズーム。正面・側面・上面・全体表示、グリッド、ワイヤーフレーム。
- ソース閲覧・保存、GLB保存、プロジェクト保存・読み込み。
- 履歴は最大20版。過去版から修正すると、それ以降の履歴を置き換える。
- 失敗時は直前の成功版を維持。撮影等でWorkerを終了した場合はソースを残し「再表示」で復帰。
- 「生成の詳細」は初期状態で閉じ、最新の生成試行について出力、推論テキスト（上流が提供した場合）、失敗段階、終了理由、使用トークンを表示する。次の生成で更新し、プロジェクトには保存しない。長いテキストは表示用に省略する。

## 生成コードの契約

```javascript
async function createModel({ THREE, addons, seed }) {
  const modelRoot = new THREE.Group();
  const mesh = new THREE.Mesh(
    new THREE.BoxGeometry(1, 1, 1),
    new THREE.MeshStandardMaterial({ color: 0x8aab66 }),
  );
  mesh.position.y = 0.5;
  modelRoot.add(mesh);
  return { modelRoot };
}
```

- 戻り値は静的モデルの `modelRoot`。メートル単位、+Yが上、+Zが正面、底面はy=0を指示する。
- 名前付き関数、または `const/let/var createModel = ...` を受け付ける。対応する `export` を実行前に取り除く。TypeScript構文の変換はしない。
- addons: `BufferGeometryUtils`、`RoundedBoxGeometry`、`ConvexGeometry`。
- 任意のBufferGeometry、数式、関数、ループ、曲線、押し出し、回転体を利用できる。固定の形状DSLは使用しない。
- DOM、window、document、外部import、ファイル、ネットワーク、レンダラー、カメラ、ライトはモデルから利用しない。手続き的画像はOffscreenCanvas / DataTexture等で作成する。
- seedはモデル構築用。APIのサンプリングseedには使用せず、新規生成の再現性を保証しない。
- `finish_reason: stop` の完全な応答だけを受け付ける。途中終了・空応答は実行しない。
- 完全なソースの契約違反、実行・検査エラーに最大1回の修復を行う。修復時は元ソースに行番号を付けて渡し、モデルは原則として行番号と元行の厳密照合を伴う部分編集を返す。広範囲の修正ではソース全文も返せる。追加修正・自動修復とも、編集応答の形式・行照合に失敗した場合は元ソースを変えずに各段階で最大3回まで編集応答を試す。編集が適用された後もコードの実行・検査に失敗した場合、自動修復は1回だけ行い、その修復後も失敗すれば終了する。通信障害や途中終了は自動再試行しない。

## 既定値と上限

| 設定             |  既定値 |                                          UI/APIの許容範囲 |
| ---------------- | ------: | --------------------------------------------------------: |
| 出力トークン     |  16,384 |                                              256〜262,144 |
| API待機          |   300秒 |                                                5〜1,800秒 |
| temperature      |    0.65 |                                                      0〜2 |
| Worker実行期限   |    20秒 |                                                  2〜120秒 |
| 三角形数         | 500,000 |                                          1,000〜2,000,000 |
| メッシュ数       |   2,000 |                                                10〜10,000 |
| テクスチャの各辺 | 2,048px |                                              128〜4,096px |
| reasoning effort | API既定 | API既定 / none / low / medium / xhigh（対応サーバーのみ） |

APIの許容範囲とモデルの実際の上限は別です。モデル側のコンテキストには入力ソース・画像・出力が含まれます。

固定上限: 指示16,000文字、ソース500,000文字、seed 0〜2,147,483,647、画像4枚（各data URL 2,800,000文字以内）、上流応答4MiB、Geometry・テクスチャの構築後推定データ256MiB、GLB 128MiB。文字数とバイト数の制限は同一ではありません。

## GLB

WorkerでGLTFExporterを実行し、モデル本体だけを書き出します。ビューアのグリッド、標準カメラ・照明は含みません。ワイヤーフレームの表示状態は書き出す素材を変えません。

書き出し後、新しいGLTFLoaderで読み込み、寸法・位置・メッシュ数・三角形数・テクスチャ数を検査します。許容差はモデルスケールの1%です。画素一致、法線の見た目、自己交差、水密性の検査ではありません。

標準PBR / Basicの静的メッシュが対象です。ShaderMaterial、独自コールバック、変位マップ等の保持できない表現は警告してGLB保存を止め、プレビューを残します。独自シェーダーのベイクやアニメーションへの変換は行いません。

## プロジェクト形式

`.qmodel` はZIPで、`project.json`、`sources/<版>.js`、`references/<版>-<画像>.txt` を含みます。

識別子は `format: "qwen-model-studio"`、`version: 1`。three.js / addonsの一致を検証し、履歴位置、ソース参照、指示、seed、時刻、モデル識別名、修復フラグ、参照画像を保存します。計測値も保存しますが、復元時は再実行したモデルの統計を表示し、過去のAPI計測値は復元しません。

APIキーとBase URLは含みません。GLBは元のコードを含まないため、GLBだけからプロジェクトを復元できません。読み込みは圧縮32MiB、展開合計64MiB、120エントリ、履歴20版まで。大きな履歴は保存できても読み込み上限に達する場合があり、画像や履歴を絞って保存してください。

## 状態・保存・停止

上流ジョブはサーバー全体で同時に1件。候補モデルは別Workerで検査し、成功後に現行版を置き換えて旧リソースを破棄します。ページの再読込・終了で未保存の履歴は失われます。

停止はHTTPリクエストと候補Workerを中止します。WSで開始済みの計算が即座に止まるかは上流によります。キーを除く設定は `.local/settings.json` に保存し、キーはサーバー終了時に消失します。
